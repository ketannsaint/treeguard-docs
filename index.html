Supported workflow

  • Jira Cloud company-managed projects.
  • Add a saved subtask tree to an issue you are already looking at, from the issue view.
  • One root issue plus its child issues and subtasks, up to twelve issues per run.
  • As many run-time values as the process needs, such as version or customer.
  • Due dates as whole-day offsets from the run, and assignment to whoever runs the template.
  • Root summary, description, and labels; subtask summaries.
  • Project-admin templates and private per-user execution receipts.

Permissions

Tree creation runs as the current Jira user. It requires Create Issues, Edit Issues, and Delete Issues so recovery markers can be removed and partial trees can be compensated. Template management requires project administration permission.

Honest product boundary

Jira does not expose transactional issue creation. The app performs best-effort reverse-order compensation and reports manual_cleanup_required when it cannot prove a clean result. It does not claim guaranteed rollback or zero orphan issues.
